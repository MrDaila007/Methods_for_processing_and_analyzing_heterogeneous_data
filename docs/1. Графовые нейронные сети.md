# Почему именно графы?
Граф — визуальное представление набора узлов (вершин) и рёбер, соединяющих эти узлы
Преимущества графового представления:
Моделирование сложных систем и отношений
Анализ взаимосвязей между сущностями
Выявление скрытых структур и закономерностей
Гибкость: произвольное количество узлов и рёбер

# Табличные данные vs Графовые данные
Табличный формат:
Строки = объекты, столбцы = признаки
Не отражает связи между объектами

Графовый формат:
Узлы = объекты с атрибутами
Рёбра = отношения между объектами
Сохраняет структурную информацию

Пример: генеалогическое древо нагляднее представлять как граф, чем как таблицу

# Определение и свойства графа
| Тип | Описание | Пример в NetworkX |
| --- | --- | --- |
| Неориентированный | Ребра без направления | nx.Graph() |
| Ориентированный | Ребра имеют направление (стрелки) | nx.DiGraph() |
| Взвешенный | Ребра имеют вес (стоимость, расстояние) | add\_edges\_from(..., weight=...) |
| Связный | Существует путь между любыми двумя узлами | nx.is\_connected() |
Граф — математическая структура G=(V,E)G=(V,E):
V (Vertices/Nodes) — набор вершин (узлов)
E (Edges) — набор ребер (связей)

# Меры центральности
| Мера | Описание | Когда использовать |
| --- | --- | --- |
| Degree Centrality | Количество связей узла | Поиск самых «популярных» узлов |
| Closeness Centrality | Средняя длина кратчайшего пути до всех узлов | Поиск узлов, быстро передающих информацию |
| Betweenness Centrality | Частота появления узла на кратчайших путях | Поиск «узких мест» или мостов в сети |

# Алгоритм поиска в ширину
Breadth-First Search
Принцип: Обход уровня за уровнем (от корня к соседям, затем к соседям соседей)
Структура: Очередь (Queue)
Применение:
Поиск кратчайшего пути в невзвешенном графе
Проверка связности
Веб-краулинг
Сложность: O(∣V∣+∣E∣)

![](ContentPlaceholder6.jpg)

<!-- Slide number: 24 -->
# Поиск в глубину (depth-first search)
Depth-First Search
Принцип: Обход вглубь каждой ветви перед возвратом (backtracking)
Структура: Стек (Stack) или Рекурсия
Применение:
Поиск циклов
Топологическая сортировка
Поиск компонент связности
Сложность: O(∣V∣+∣E∣)
Риск: Возможны бесконечные циклы без проверки посещенных узлов

# Архитектура DeepWalk
Набор данных – это Клуб карате Закари. Он представляет отношения между участниками Клуба карате, который изучал Уэйн В. Закари в 1970-х годах.

Это своего рода социальная сеть, в которой каждый узел является участником, а участники, взаимодействующие друг с другом за пределами клуба, связаны между собой.

Данные об участниках разделены на два класса: мы хотели бы присвоить правильный класс каждому участнику (классификация узлов), просто посмотрев его связи с другими участниками.
Преимущества:
 Обучение без учителя (не требует размеченных данных)
 Масштабируемость за счёт H-Softmax
 Сохраняет структурную близость узлов
 Готовые эмбеддинги для любых downstream-задач

# Итоги DeepWalk
Результаты применения DeepWalk:
Обучение без учителя: Поиск сходства узлов через косинусное расстояние
Обучение с учителем: Использование эмбеддингов для классификации
Точность: Модель показала правильность 95.45% на тестовой выборке (Клуб карате)

Ограничения:
Равновероятные случайные блуждания (не учитывают структуру окружения)
Отсутствие гибкости в исследовании локальной vs глобальной структуры
Node2Vec решает эти проблемы через смещенные случайные блуждания.

<!-- Slide number: 43 -->
# Node2Vec
| Компонент | DeepWalk | Node2Vec |
| --- | --- | --- |
| Генерация данных | Равновероятные случайные блуждания | Смещенные случайные блуждания |
| Обучение | Word2Vec (Skip-gram) | Word2Vec (Skip-gram) |
| Гибкость | Низкая | Высокая (параметры p, q) |
Node2Vec (Grover & Leskovec, 2016) — архитектура, основанная на DeepWalk

Ключевая идея:Изменяя стратегию обхода, мы влияем на то, какие свойства сети (локальные или глобальные) будут закодированы в эмбеддингах.

<!-- Slide number: 44 -->
# Стратегии исследования окрестностей
Два подхода к определению «соседства»:
BFS (Поиск в ширину)  Структурная эквивалентность
Исследует ближайших соседей
Узлы эквивалентны, если у них много общих соседей
Пример: Хабы в сети, повторяющиеся роли
DFS (Поиск в глубину)  Гомофилия
Исследует удаленные узлы
Узлы схожи, если они соединены (принадлежат одному сообществу)
Пример: Участники одной социальной группы

Node2Vec ищет компромисс между этими стратегиями.

# Роль параметров p и q
| Параметр | Высокое значение | Низкое значение |
| --- | --- | --- |
| p (Возврат) | Маловероятно вернуться назад(Исследование новых узлов, DFS) | Высокая вероятность возврата(Локальное блуждание) |
| q (Вход-Выход) | Движение к близким узлам(BFS, локальная структура) | Движение к удаленным узлам(DFS, глобальная структура) |

# Разработка рекомендательной системы фильмов на основе Node2Vec
Необходимо построить рекомендательную систему фильмов, используя подход Graph-based Learning. В отличие от традиционных методов (коллаборативная фильтрация), представите фильмы как узлы графа, где связи отражают скрытые семантические сходства, выявленные через поведение пользователей.
Основой решения станет алгоритм Node2Vec, который позволяет гибко настраивать стратегию обхода графа для захвата различных свойств сети (гомофилия vs структурная эквивалентность).

# Этапы выполнения
Построение графа связей фильмов:
Фильтрация: Оставляем только высокие рейтинги (≥ 4)
Ко-вхождение: Считаем, сколько раз два фильма понравились одному пользователю
Рёбра: Создаем взвешенное ребро, если счетчик ≥ 20
Итог: 410 узлов (фильмов), 14 936 рёбер

Логика:Фильмы, которые нравятся одним и тем же людям, структурно близки в графе → их эмбеддинги будут похожи.
