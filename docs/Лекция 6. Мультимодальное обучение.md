RGB-изображение — цветное фото библиотеки.
Depth-карта — черно-белое изображение, где яркость каждого пикселя соответствует расстоянию от камеры до объекта (чем светлее — тем дальше).

Поскольку обе модальности описывают одну и ту же сцену и имеют одинаковые размеры (разрешение), их можно объединить. В результате получается входной тензор с 4 каналами: 3 канала RGB (красный, зелёный, синий) + 1 канал глубины.

Когда этот подход работает:
Модальности должны быть очень близки по своей природе и структуре. Например, RGB и глубина, или два разных снимка одного объекта с разных камер.
Модель может использовать пространственные корреляции между каналами (например, знать, что объекты на переднем плане (глубина = малая) часто имеют более чёткие края на RGB-изображении).
Ограничения:
Этот метод не подходит для несопоставимых модальностей, таких как текст и изображение. Вы не можете просто склеить строку текста с матрицей пикселей.
Он требует, чтобы все модальности имели одинаковое пространственное разрешение.
Модель должна быть способна обрабатывать многоканальные входы (что большинство современных CNN умеют делать).

# Мультимодальное обучение
import torch
import torch.nn as nn

class FourChannelCNN(nn.Module):
    def __init__(self, num_classes=10):
        super(FourChannelCNN, self).__init__()
        # Первый свёрточный слой: 4 входных канала -> 32 выходных
        self.conv1 = nn.Conv2d(4, 32, kernel_size=3, padding=1)
        self.relu = nn.ReLU()
        self.pool = nn.MaxPool2d(2, 2)
        # Полносвязный слой для классификации
        self.fc = nn.Linear(32 * 16 * 16, num_classes) # Предполагаем вход 32x32

    def forward(self, x):
        # x: [batch_size, 4, H, W]
        x = self.conv1(x) # [batch_size, 32, H, W]
        x = self.relu(x)
        x = self.pool(x) # [batch_size, 32, H/2, W/2]
        x = x.view(x.size(0), -1) # Flatten
        x = self.fc(x) # [batch_size, num_classes]
        return x

# Создание модели
model = FourChannelCNN(num_classes=5)

# Пример входных данных (батч из 2 изображений 32x32 с 4 каналами)
input_data = torch.randn(2, 4, 32, 32)
output = model(input_data)
print(output.shape) # torch.Size([2, 5])

CNN-слои (Conv2D) по умолчанию могут работать с любым количеством входных каналов. Они просто применяют набор фильтров, каждый из которых «смотрит» на все каналы одновременно, чтобы извлечь признаки.

МРТ/КТ + контраст: Иногда используются разные последовательности сканирования, которые можно объединить в один 4-канальный вход для лучшей диагностики.
УЗИ + допплеровское изображение: Допплеровские данные могут быть представлены как отдельный канал, содержащий информацию о скорости кровотока.
C. Аэро- и космическая съёмка
Мультиспектральные и гиперспектральные изображения: Камеры спутников или дронов часто снимают в десятках или сотнях спектральных каналов (не только видимый свет, но и инфракрасный, ультрафиолетовый и др.). Модели, такие как U-Net или ResNet, легко адаптируются под такой вход.
D. Видеообработка
RGB + Optical Flow: Оптический поток (движение пикселей между кадрами) может быть представлен как два дополнительных канала (u, v — горизонтальная и вертикальная составляющие движения). Таким образом, для одного кадра можно использовать 5 каналов (3 RGB + 2 оптического потока).

Зачем использовать MLP для фьюзинга?
Простая конкатенация векторов— это линейная операция. Она просто склеивает данные, но не учитывает, как они взаимодействуют друг с другом.
MLP же позволяет:
Моделировать нелинейные взаимодействия: Например, если в одном векторе есть слово «большой», а в другом — объект с большим размером, MLP может научиться связывать эти два факта.
Извлекать более сложные признаки: MLP может выделить важные комбинации признаков из объединённого вектора, которые были бы незаметны при простом слиянии.
Уменьшать размерность: Если объединённый вектор слишком длинный, MLP может его сжать до более компактного представления, сохранив самую важную информацию.

Цель мультимодального обучения — не просто обработать разные типы данных, а научить модель понимать связи между ними. Для этого необходимо, чтобы латентные представления (векторы) семантически связанных объектов из разных модальностей находились близко друг к другу в общем латентном пространстве.

Синий круг и красный треугольник — это два разных типа данных, которые должны быть связаны (например, изображение «собака» и текст «собака»).
Каждый проходит через свой энкодер, создавая латентный вектор (синий и красный прямоугольники).
Контрастивная функция потерь (contrastive loss) вычисляется между этими двумя векторами.
Эта функция штрафует модель, если векторы далеки друг от друга, и поощряет, если они близки.

# Мультимодальное обучение
Что такое контрастивная функция потерь?
Контрастивная функция потерь — это механизм, который обучает модель так, чтобы:

Положительные пары (связанные данные, например, фото собаки и слово «собака») имели близкие латентные векторы.
Отрицательные пары (несвязанные данные, например, фото собаки и слово «стул») имели далёкие латентные векторы.

![](Объект3.jpg)

![](Рисунок4.jpg)
L = y * d² + (1 - y) * max(0, margin - d)²

y — метка (1 для положительной пары, 0 для отрицательной),
d — расстояние между векторами (обычно косинусное или евклидово),
margin — пороговое значение, после которого отрицательные пары не штрафуются.

# Мультимодальное обучение
Основная идея:
Для создания мощной мультимодальной модели, способной не только генерировать описание изображения, но и понимать связь между визуальным и текстовым контентом, используется комбинация двух функций потерь:

Потеря выравнивания (alignment loss) — заставляет латентные векторы изображения и текста быть близкими друг к другу.

Потеря реконструкции (reconstruction loss) — заставляет модель точно воссоздавать исходный текст на основе латентного представления.

Stage 1: Composable Conditioning (a)

На этом этапе модель обучается выравнивать латентные представления разных модальностей в едином пространстве.

Входные данные (текст, видео, изображение, звук) проходят через свои специализированные энкодеры.

Эти выровненные векторы используются для условной генерации с помощью диффузионных моделей (по одной на каждую модальность: Text UNet, Vision UNet, Audio UNet).
Модель обучается минимизировать L2 Loss между предсказанными и истинными латентными векторами на каждом шаге диффузии.

Этот этап позволяет модели научиться понимать связи между разными модальностями, что является ключевым для any-to-any generation.

Этап Training (Обучение):
Входные данные: Изображение + текстовое описание (например, «A small red boat on the water»).
Vision Encoder: Преобразует изображение в последовательность эмбеддингов (векторов). Это может быть ViT или CNN.
Text Embedder: Преобразует текст в последовательность токенов.

Цель обучения: Научить модель генерировать правильное текстовое описание изображения, используя замороженную языковую модель. Для этого обучается проектор (или адаптер), который преобразует визуальные признаки в формат, понятный языковой модели.

Этап Testing (Тестирование):
На этом этапе модель решает новые задачи без дополнительного обучения (zero-shot или few-shot learning).
0-shot VQA (Zero-shot Visual Question Answering):
Входные данные: Изображение + вопрос (например, «What colour is the car?»).
Модель использует свои знания, полученные на этапе обучения, чтобы ответить на вопрос, даже если она никогда не видела подобных вопросов раньше.
Few-shot image classification:
Входные данные: Несколько примеров изображений с подписями (например, «This is a dax», «This is a blicket») + новое изображение с вопросом «What is this?».
Модель использует эти примеры для классификации нового изображения, демонстрируя способность к few-shot learning.

Вместо того чтобы обучать классификатор на изображениях, мы создаём текстовые шаблоны для каждого класса (например, «A photo of a {class}»).
Эти шаблоны подаются в Text Encoder, который создает латентные векторы для каждого класса.
Таким образом, у нас есть векторы-шаблоны для всех классов, которые можно использовать для классификации.

<!-- Slide number: 29 -->

![](Рисунок3.jpg)
(3) Use for zero-shot prediction (Использование для zero-shot предсказания)
На этом этапе модель используется для классификации новых изображений, которых не было в обучающих данных.
Изображение подаётся в Image Encoder, который создает его латентный вектор.
Этот вектор сравнивается со всеми векторами-шаблонами классов (полученными на этапе 2) с помощью косинусного сходства.
Класс с максимальным сходством выбирается как ответ.

# Визуальный вопросно-ответный механизм
Входное изображение: Изображение подаётся на вход предобученной CNN (например, VGGNet). CNN обрабатывает изображение и выдаёт вектор признаков длиной 4096. Этот вектор является латентным представлением изображения.
Текстовый вопрос: Вопрос «How many horses are in this image?» подаётся на вход LSTM, который кодирует его в вектор признаков длиной 1024.
Фьюзинг (объединение): Латентные векторы от CNN и LSTM объединяются с помощью поэлементного умножения (pointwise multiplication). Это простой, но эффективный способ создания нового вектора, который содержит информацию и из изображения, и из вопроса.
Классификация: Объединённый вектор подаётся на вход нескольких полносвязных слоёв (fully-connected layers), которые преобразуют его в вектор вероятностей для каждого возможного ответа.
Выход: На выходе модель выдаёт наиболее вероятный ответ (в данном случае — «2»).

# Мультимодальные диалоговые системы

![](Рисунок3.jpg)
Интеграция двух ключевых мультимодальных задач — генерации подписей к изображениям (Image Captioning) и поиска изображений по тексту (Image Retrieval) — в единую систему на основе Large Language Model (LLM).

Входное изображение: Изображение силуэта самолёта на фоне заката.
Encoder: Преобразует изображение в латентный вектор.
LLM: Получает латентный вектор от энкодера и генерирует текстовое описание: «silhouette of a plane against the sunset». В конце описания добавляется токен [RET], который указывает на то, что этот текст будет использоваться для поиска (retrieval).
Сравнение (compare): Сгенерированное описание сравнивается с описаниями других изображений в базе данных.
Поиск (retrieval): Найдено изображение, которое имеет схожее описание.
Выравнивание (aligned): Латентный вектор найденного изображения выравнивается с латентным вектором исходного изображения, что подтверждает их семантическую близость.

# Визуальная и языковая навигация

![](Объект3.jpg)

![](Рисунок4.jpg)
некоторых мультимодальных задачах, таких как навигация по визуальным инструкциям (VLN), изображения можно рассматривать как последовательность кадров, подобную видео. В этом случае использование LSTM для их обработки становится логичным, так как LSTM специально предназначен для работы с последовательными данными.

<!-- Slide number: 55 -->

![](Рисунок7.jpg)
VLN (Vision-and-Language Navigation):
Входные данные: Текстовая инструкция (например, «Move inside and ... to the formal dining table») и последовательность изображений, полученных агентом во время навигации.
Цель: Агент должен выполнить серию действий (a1, a2, a3, ...), чтобы достичь цели, описанной в инструкции.
Почему LSTM?
Изображения, полученные агентом, представляют собой временную последовательность (как кадры видео).
LSTM может использовать свою скрытую память для отслеживания контекста и истории наблюдений, что критически важно для навигации.
Например, агент помнит, где он был раньше, и использует эту информацию для принятия решения о следующем действии.

VQA (Visual Question Answering):
Входные данные: Текстовый вопрос (например, «What color is the bike?») и изображение.
Цель: Ответить на вопрос, основываясь на содержании изображения.
Почему LSTM?
Хотя в классической VQA используется только одно изображение, в некоторых вариантах задачи (например, Video QA) входными данными являются видео или последовательность изображений.
В этих случаях LSTM также может быть полезен для анализа временной динамики.
