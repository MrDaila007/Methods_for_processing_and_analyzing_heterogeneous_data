## 1. Несбалансированные данные в машинном обучении

### 1.1. Базовый контекст машинного обучения

В презентациях сначала вводится общий контекст машинного обучения:

- традиционное программирование задает правила вручную, а машинное обучение выводит правила из данных и правильных ответов;
- алгоритм машинного обучения - это процедура обучения, например решающее дерево, SVM, нейронная сеть;
- модель - это результат обучения алгоритма на данных, то есть набор параметров, весов, правил или структуры, применяемый к новым объектам;
- типичные задачи классификации делятся на бинарные и многоклассовые.

Для лабораторных это означает, что при построении решения нужно различать:

- данные и признаки;
- алгоритм;
- обученную модель;
- метрики качества;
- процедуру валидации.

### 1.2. Что такое дисбаланс классов

Датасет считается несбалансированным, если объекты распределены между классами неравномерно. В материалах приводятся ориентировочные уровни дисбаланса:

- mild imbalance: миноритарный класс составляет 20-40%;
- moderate imbalance: 1-20%;
- severe imbalance: менее 1%.

В задачах дисбаланса обычно есть:

- majority class - доминирующий класс;
- minority class - редкий класс, который часто является наиболее важным;
- imbalance ratio - отношение количества объектов меньшего класса к большему.

Примеры задач с дисбалансом:

- медицинская диагностика;
- выявление мошенничества;
- прогноз дефолта;
- churn prediction;
- обнаружение аномалий;
- intrusion detection;
- claim prediction.

Главная проблема: обычные модели склонны оптимизировать качество на большинстве и игнорировать редкий класс. Например, при 0.5% больных модель, всегда отвечающая "здоров", даст 99.5% accuracy, но будет бесполезна.

### 1.3. Почему дисбаланс возникает

Основные причины:

- редкость события в предметной области;
- ошибки сбора данных или разметки;
- смещенная выборка;
- ограниченность данных по времени, региону, устройствам или пользователям;
- высокая стоимость повторного сбора и переразметки данных.

В лабораторных это важно на этапе EDA: перед обучением модели нужно посмотреть распределение классов и понять, можно ли доверять выборке.

## 2. Data-Level подход к дисбалансу

Data-Level методы меняют сам обучающий набор данных до обучения модели.

### 2.1. Oversampling

Oversampling увеличивает число объектов миноритарного класса.

Основные варианты:

- Random Oversampling - случайное дублирование объектов меньшего класса;
- SMOTE - генерация синтетических объектов между существующими объектами меньшего класса и их ближайшими соседями;
- Borderline-SMOTE - генерация новых объектов преимущественно около границы классов;
- ADASYN - адаптивная генерация большего числа объектов в трудных областях, где миноритарный класс окружен majority-объектами.

Плюсы oversampling:

- не удаляет исходные данные;
- полезен при малом числе объектов;
- часто дает заметный прирост качества для редкого класса.

Минусы:

- может приводить к переобучению;
- синтетические объекты могут быть нереалистичными;
- увеличивает размер обучающей выборки и время обучения;
- ADASYN и похожие методы могут усиливать шум.

### 2.2. Undersampling

Undersampling уменьшает число объектов majority-класса.

Основные варианты:

- Random Undersampling - случайное удаление объектов большинства;
- Tomek Links - удаление majority-объектов, находящихся в парах ближайших соседей с объектами другого класса;
- ENN, Edited Nearest Neighbours - удаление объектов, чья метка не согласуется с метками ближайших соседей;
- CNN, OSS, NearMiss, Cluster Centroids и другие методы отбора или сжатия majority-класса.

Плюсы undersampling:

- ускоряет обучение;
- помогает очистить границу классов;
- применим для очень больших датасетов.

Минусы:

- может удалить полезную информацию;
- случайное удаление нестабильно;
- kNN-based методы чувствительны к метрике расстояния и параметру k;
- некоторые методы вычислительно дорогие.

### 2.3. Hybrid Sampling

Гибридные методы объединяют oversampling и undersampling:

- SMOTE-ENN;
- SMOTE-Tomek;
- ADASYN + Cluster Centroids;
- другие комбинации генерации minority-объектов и очистки majority-областей.

Идея: сначала добавить информацию о меньшем классе, затем удалить шумные или неоднозначные объекты.

Практический вывод из презентации: гибридные методы стоит применять, когда важна максимальная точность и есть вычислительные ресурсы. Но нельзя считать, что стандартная комбинация всегда улучшит качество: если отдельные методы не дают прироста, их комбинация тоже может ухудшить результат.

### 2.4. Практические результаты из материалов

В экспериментах рассматривались датасеты:

Ключевые выводы:

## 3. Algorithm-Level подход к дисбалансу

Algorithm-Level методы не обязательно меняют данные. Они меняют обучение модели, функцию потерь, веса классов, процедуру ансамблирования или постановку задачи.

### 3.1. Метрики для несбалансированной классификации

Главная мысль: accuracy часто вводит в заблуждение.

Вместо нее нужно использовать метрики, которые явно учитывают minority-класс:

- confusion matrix;
- precision;
- recall / sensitivity / true positive rate;
- specificity / true negative rate;
- F1-score;
- F-beta;
- balanced accuracy;
- G-mean;
- MCC;
- ROC-AUC;
- PR-AUC;
- log loss;
- Brier score.

Практическая интерпретация:

- precision показывает, насколько предсказанные положительные ответы действительно положительные;
- recall показывает, насколько хорошо модель находит положительный класс;
- F1 балансирует precision и recall;
- balanced accuracy усредняет качество по классам;
- PR-AUC часто полезнее ROC-AUC при сильном дисбалансе;
- выбор метрики зависит от цены FP и FN.

Для лабораторных важно заранее определить, что хуже:

- false positive - ложная тревога;
- false negative - пропуск важного случая.

Например, в медицине и fraud detection часто важнее recall, потому что пропуск болезни или мошенничества дороже лишней проверки.

### 3.2. Cost-Sensitive Learning и class weighting

Cost-sensitive learning учитывает, что ошибки разных типов имеют разную цену.

Идея:

- ошибку на minority-классе штрафуют сильнее;
- функция потерь получает веса классов;
- модель начинает уделять больше внимания редким объектам.

В scikit-learn это часто делается через `class_weight`:

- `class_weight="balanced"`;
- ручной словарь весов;
- подбор весов как гиперпараметров.

Плюсы:

- просто включить;
- не меняет обучающие данные;
- поддерживается многими моделями: Logistic Regression, SVM, DecisionTree, RandomForest и др.

Минусы:

- может переобучиться на шуме minority-класса;
- может ухудшить precision;
- не всегда достаточно при экстремальном дисбалансе.

Практическая рекомендация из презентации: для умеренного дисбаланса начинать с `class_weight`, а при сильном дисбалансе сравнивать несколько схем взвешивания.

Рассматривались подходы:

- inverse frequency;
- logarithmic weighting;
- effective number of samples;
- adaptive weighting.

Вывод: стандартный inverse frequency не всегда оптимален; веса нужно включать в процедуру подбора гиперпараметров.

### 3.3. Ансамблевые методы

Ансамбли объединяют несколько моделей, чтобы повысить устойчивость и качество.

Основные типы:

- bagging и Random Forest - параллельное обучение моделей на разных подвыборках;
- boosting - последовательное обучение, где новые модели исправляют ошибки предыдущих;
- XGBoost, CatBoost, LightGBM - распространенные boosting-реализации.

Для дисбаланса применяются специальные ансамбли:

- Balanced Random Forest;
- RUSBoost;
- EasyEnsemble.

Идея Balanced Random Forest: каждое дерево обучается на более сбалансированной bootstrap-подвыборке, где majority-класс уменьшается или minority-класс усиливается.

Когда использовать:

- сильный дисбаланс;
- достаточно вычислительных ресурсов;
- важна производительность больше, чем простая интерпретируемость.

### 3.4. Anomaly Detection как крайний случай дисбаланса

Если minority-класс очень редкий, задачу можно рассматривать как обнаружение аномалий.

Методы:

- One-Class SVM;
- Isolation Forest;
- автоэнкодеры.

Когда использовать:

- minority-класс менее 1%;
- мало размеченных примеров редких событий;
- rare class плохо определен;
- нужно искать отклонения от нормы.

Ограничения:

- сложно настраивать;
- модель может не выучить семантические признаки minority-класса;
- нужна аккуратная валидация precision/recall.

## 4. Графовое обучение и GNN

### 4.1. Почему графы

Граф представляет данные как:

- узлы - объекты;
- ребра - связи между объектами;
- признаки узлов, ребер и всего графа.

Графы удобны, когда важны отношения:

- социальные сети;
- рекомендательные системы;
- транспортные сети;
- финансовые связи;
- биологические и молекулярные структуры;
- графы знаний;
- программные зависимости.

Даже данные, которые на первый взгляд не являются графами, можно представить графово:

- изображение: пиксели как узлы, соседство пикселей как ребра;
- текст: слова как узлы, синтаксические или семантические связи как ребра;
- временные данные: динамически изменяющиеся узлы и связи.

### 4.2. Основные задачи обучения на графах

В материалах выделены задачи:

- классификация узлов;
- регрессия узлов;
- прогнозирование ребер;
- классификация графов;
- генерация графов;
- рекомендательные системы на основе графов.

Для лабораторных особенно важны:

- построение графа из исходных данных;
- выбор признаков узлов;
- выбор правила создания ребер;
- обучение эмбеддингов;
- использование эмбеддингов для downstream-задачи.

### 4.3. Базовая теория графов

Разбирались:

- неориентированные графы;
- ориентированные графы;
- взвешенные графы;
- связные и несвязные графы;
- деревья;
- DAG;
- двудольные графы;
- полные графы.

Также вводились меры:

- degree centrality - количество связей узла;
- closeness centrality - средняя близость до остальных узлов;
- betweenness centrality - насколько часто узел лежит на кратчайших путях;
- density - плотность графа.

Алгоритмы обхода:

- BFS - обход в ширину, полезен для кратчайших путей в невзвешенном графе и проверки связности;
- DFS - обход в глубину, полезен для поиска циклов, компонент связности и топологической сортировки.

### 4.4. DeepWalk

DeepWalk переносит идею Word2Vec на графы.

Соответствие:

- слово -> узел;
- предложение -> последовательность случайного блуждания;
- контекст слова -> соседние узлы в блуждании;
- эмбеддинг слова -> эмбеддинг узла.

Процесс:

1. Запускаются случайные блуждания по графу.
2. Получаются последовательности узлов.
3. Эти последовательности обучаются как "предложения" в Word2Vec, обычно через Skip-gram.
4. На выходе получается векторное представление каждого узла.

Плюсы DeepWalk:

- обучение без учителя;
- масштабируемость;
- сохранение структурной близости;
- эмбеддинги можно использовать для классификации, поиска похожих узлов и рекомендаций.

Ограничение: случайные блуждания равновероятны и плохо управляют тем, какую структуру графа захватывать - локальную или глобальную.

### 4.5. Node2Vec

Node2Vec развивает DeepWalk за счет смещенных случайных блужданий.

Ключевая идея: параметры `p` и `q` управляют стратегией обхода.

- высокий `p` снижает вероятность немедленного возврата назад;
- низкий `p` делает возврат более вероятным;
- высокий `q` склоняет обход к локальной BFS-подобной стратегии;
- низкий `q` склоняет обход к более дальней DFS-подобной стратегии.

Две важные структуры:

- BFS-like обход помогает находить структурную эквивалентность, например похожие роли или hubs;
- DFS-like обход помогает находить гомофилию, то есть принадлежность к одному сообществу.

Лабораторная работа из презентации:

- построить рекомендательную систему фильмов на основе Node2Vec;
- использовать MovieLens 100k;
- оставить высокие рейтинги, например `rating >= 4`;
- считать ко-встречаемость фильмов у пользователей;
- создать взвешенные ребра между фильмами, которые часто понравились одним и тем же пользователям;
- обучить Node2Vec;
- использовать близость эмбеддингов для рекомендаций.

### 4.6. Простые GNN, MLP и GCN

В продолжении лекции рассматриваются графовые датасеты:

- Cora: 2708 публикаций, ребра цитирования, 1433 bag-of-words признака, 7 классов;
- Facebook Page-Page: 22470 страниц Facebook, ребра взаимных лайков, 128 признаков, 4 класса.

Задание: построить MLP и GNN для Facebook Page-Page.

Смысл сравнения:

- MLP использует признаки узлов, но не использует структуру графа;
- GNN использует и признаки узлов, и информацию о соседях.

GCN, Graph Convolutional Network:

- предложена Kipf и Welling в 2017 году;
- является базовой и популярной архитектурой GNN;
- агрегирует признаки соседей;
- добавляет self-loop, чтобы узел учитывал собственные признаки;
- нормализует вклад соседей по степеням узлов.

Проблема простого GNN-слоя: узлы с большим числом соседей могут получать эмбеддинги с сильно большими значениями. Решение GCN - нормализация через матрицу степеней, чтобы признаки узлов с разным числом соседей были сопоставимы.

Практический вывод: GCN особенно полезна на графах с большим разбросом степеней, например Cora и Facebook Page-Page.

Также упоминалась регрессия узлов на Wikipedia page-page сетях, где нужно предсказывать среднемесячный трафик статьи.

## 5. Унимодальное обучение

Унимодальное обучение работает с одной модальностью данных за раз.

В лекции перечисляются основные типы унимодальных представлений:

- визуальная модальность;
- языковая модальность;
- акустическая модальность;
- тактильные данные;
- робототехнические датчики силы и момента;
- табличные данные;
- другие специализированные сигналы.

Важная часть лекции - базовая схема обучения:

- train set - данные для обучения параметров модели;
- validation set - данные для выбора гиперпараметров и настройки модели;
- test set - данные для финальной оценки;
- k-fold cross-validation - вариант оценки при малом количестве данных.

Пример гиперпараметра: `k` в k-nearest neighbors.

- при `k = 1` модель склонна переобучаться;
- при слишком большом `k` модель чрезмерно сглаживает границы;
- выбирать `k` нужно по validation или cross-validation.

Для лабораторных это базовый шаблон: разделить данные, обучить модель, подобрать гиперпараметры, оценить на тесте.

## 6. Мультимодальное обучение

### 6.1. Что такое мультимодальность

В машинном обучении мультимодальность означает работу с несколькими типами информации:

- текст;
- речь;
- изображение;
- видео;
- жесты;
- мимика;
- поза;
- аудио;
- физиологические сигналы;
- depth, thermal, fMRI, GSR, ЭКГ и др.

Мультимодальность особенно важна, когда смысл возникает из сочетания сигналов. Например, фраза "Мне это понравилось!" может быть позитивной или саркастической в зависимости от интонации и выражения лица.

### 6.2. Исторический контекст

В лекции выделены четыре эпохи:

- поведенческая эра: жесты и речь как единый акт коммуникации;
- вычислительная эра: AVSR, мультимедийные системы, аффективные вычисления;
- эра взаимодействия: анализ совещаний, социальные сигналы, проекты AMI, CHIL, CALO;
- эра глубокого обучения: большие датасеты, GPU, attention, transformers, multimodal foundation models.

### 6.3. Пять ключевых задач мультимодального обучения

По обзору Baltrusaitis et al. выделяются пять задач.

1. Представление.

   Нужно получить признаки для разных модальностей так, чтобы они сохраняли взаимодополняемую информацию.

   Подходы:

   - joint representation - общее пространство для всех модальностей;
   - coordinated representation - отдельные пространства, связанные через сходство или структуру.

2. Выравнивание.

   Нужно найти соответствия между элементами разных модальностей.

   Примеры:

   - слово и фрагмент видео;
   - объект на изображении и текстовое описание;
   - улыбка и позитивное слово;
   - аудиофрагмент и транскрипт.

3. Трансляция.

   Нужно преобразовать данные одной модальности в другую.

   Примеры:

   - изображение -> текстовое описание;
   - речь -> жесты;
   - текст -> поза;
   - звук + текст -> видео.

4. Слияние, fusion.

   Нужно объединить модальности для решения задачи.

   Подходы:

   - early fusion - объединение признаков на входе;
   - late fusion - объединение решений моделей;
   - model-based fusion - нейросети, attention, gating, CRF и др.

5. Совместное обучение, co-learning.

   Нужно передавать знания между модальностями.

   Примеры:

   - обучение на параллельных данных;
   - zero-shot;
   - перенос знаний при нехватке одной модальности;
   - циклические потери.

### 6.5. Мультимодальное представление через каналы

Один простой вариант мультимодальности - объединить близкие по структуре данные как каналы.

Пример:

- RGB изображение имеет 3 канала;
- depth-карта добавляет четвертый канал;
- получается тензор `[batch_size, 4, H, W]`.

Это хорошо работает, когда модальности:

- имеют одинаковое пространственное разрешение;
- описывают одну и ту же сцену;
- близки по природе данных.

Примеры:

- RGB + Depth;
- RGB + Thermal;
- МРТ/КТ + контраст;
- УЗИ + допплер;
- мультиспектральные и гиперспектральные изображения;
- RGB + Optical Flow.

Ограничение: так нельзя просто объединить несопоставимые модальности вроде текста и изображения.

### 6.6. Энкодеры, латентные векторы и fusion

Более общий подход:

1. Для каждой модальности используется свой энкодер.
2. Сырые данные преобразуются в латентный вектор.
3. Векторы объединяются.
4. Объединенное представление подается в модель задачи.

Примеры энкодеров:

- CNN или ViT для изображений;
- LSTM, Transformer или LLM для текста;
- аудиоэнкодер для звука;
- специализированные энкодеры для видео, depth, medical images.

Fusion может быть:

- конкатенацией;
- поэлементным умножением;
- MLP поверх объединенного вектора;
- attention;
- gating;
- cross-modal transformer.

MLP полезен потому, что простая конкатенация только склеивает признаки, а MLP может моделировать нелинейные взаимодействия между модальностями.

### 6.7. Контрастивное обучение и общее латентное пространство

Цель многих современных мультимодальных моделей - поместить связанные объекты из разных модальностей близко в общем латентном пространстве.

Пример:

- изображение собаки и текст "собака" должны иметь близкие векторы;
- изображение собаки и текст "стул" должны быть далеки.

Контрастивная функция потерь:

- сближает положительные пары;
- отдаляет отрицательные пары;
- используется в CLIP, ALIGN, CoCa, ImageBind и похожих моделях.

Это дает:

- поиск изображения по тексту;
- поиск текста по изображению;
- zero-shot классификацию;
- перенос знаний между модальностями.

### 6.8. Alignment + Reconstruction

Для генеративных задач, например image captioning, полезна комбинация:

- alignment loss - сближает представления изображения и текста;
- reconstruction loss - заставляет модель восстанавливать или генерировать правильный текст.

Такой принцип используется в моделях вроде CoCa и BLIP, которые соединяют контрастивное и генеративное обучение.

### 6.9. CoDi и any-to-any generation

В лекции разбирается идея CoDi:

- разные модальности проходят через специализированные энкодеры;
- Bridging Alignment выравнивает латентные представления;
- диффузионные модели генерируют нужные модальности;
- модель может работать в режиме any-to-any generation.

Примеры:

- текст + звук -> изображение;
- звук + текст -> видео;
- видео + звук -> текст;
- текст -> видео + звук.

### 6.10. Замороженные foundation models

Вместо обучения всей мультимодальной системы с нуля можно:

1. Взять предобученный vision encoder, audio encoder или LLM.
2. Заморозить их веса.
3. Обучить небольшой projector, adapter или fusion-модуль.

Пример из лекции:

- изображение кодируется ViT или CNN;
- визуальные эмбеддинги преобразуются проектором;
- LLM получает визуальные эмбеддинги вместе с текстом;
- LLM генерирует описание, ответ или инструкцию.

Это важно для лабораторных, потому что такой подход намного дешевле полного обучения модели.

### 6.11. CLIP

CLIP обучается на парах изображение-текст.

Этапы:

1. Contrastive pre-training: image encoder и text encoder учатся сближать правильные пары и разделять неправильные.
2. Создание классификатора из текстовых меток: классы описываются шаблонами вроде `A photo of a {class}`.
3. Zero-shot prediction: изображение сравнивается с текстовыми векторами классов по cosine similarity.

Практические применения:

- zero-shot классификация изображений;
- image retrieval по тексту;
- text retrieval по изображению;
- построение мультимодального поиска через kNN по эмбеддингам.

### 6.12. Image Captioning

Классическая схема:

1. CNN, например ResNet или VGG, извлекает признаки изображения.
2. Эти признаки подаются в LSTM или Transformer decoder.
3. Decoder пошагово генерирует описание от `<start>` до `<end>`.

Медицинский пример:

- вход: рентгеновский снимок;
- image encoder или ViT превращает изображение в эмбеддинги;
- transformer decoder генерирует медицинское описание;
- задача требует точности и доменной осторожности.

### 6.13. Visual Question Answering

VQA получает:

- изображение;
- вопрос на естественном языке;
- ответ.

Классическая архитектура:

1. CNN кодирует изображение.
2. LSTM кодирует вопрос.
3. Векторы объединяются, например поэлементным умножением.
4. Fully-connected layers предсказывают ответ.

Современная архитектура:

- image encoder извлекает визуальные признаки;
- MLP/projector переводит их в формат LLM;
- LLM понимает вопрос и генерирует ответ.

### 6.14. Мультимодальные диалоговые системы

Мультимодальный диалоговый агент может:

- принимать изображение и текст;
- генерировать описание изображения;
- искать похожие изображения;
- вести многоходовой диалог;
- использовать LLM для рассуждений;
- генерировать или извлекать визуальный контент.

В лекции рассматривается интеграция image captioning и image-text retrieval в единой LLM-системе.

### 6.15. Vision-and-Language Navigation

VLN объединяет:

- текстовую инструкцию;
- последовательность изображений или наблюдений;
- действия агента.

Задача: выполнить маршрут или достичь цели по инструкции.

Почему важны последовательные модели:

- наблюдения агента идут во времени;
- нужно помнить, где агент уже был;
- LSTM или другие sequence-модели помогают учитывать историю.

Примеры задач:

- следование инструкциям в помещении;
- робототехника;
- AR/VR;
- автономные агенты;
- игры и среды вроде NetHack.

## 7. Как эти темы связаны с лабораторными работами

### 7.1. Общий шаблон лабораторной

Для большинства лабораторных работ полезен такой порядок:

1. Понять тип данных: табличные, графовые, текстовые, визуальные, мультимодальные.
2. Провести EDA: размеры, пропуски, распределения, дисбаланс классов.
3. Разделить данные на train/validation/test.
4. Выбрать baseline.
5. Выбрать метрики, подходящие задаче.
6. Обучить модель.
7. Улучшить модель через балансировку, веса, гиперпараметры, архитектуру или fusion.
8. Сравнить результаты с baseline.
9. Интерпретировать ошибки.

### 7.2. Если задача про дисбаланс

Нужно проверить:

- распределение классов;
- minority/majority ratio;
- выбранную метрику;
- confusion matrix;
- precision/recall/F1/PR-AUC;
- помогает ли oversampling;
- помогает ли undersampling;
- помогает ли `class_weight`;
- лучше ли ансамбли;
- не ухудшается ли качество на minority-классе.

Начинать разумно с:

- baseline без балансировки;
- `class_weight="balanced"`;
- Random Oversampling или SMOTE;
- Balanced Random Forest или другой ансамбль;
- сравнения по F1, balanced accuracy или PR-AUC.

### 7.3. Если задача про графы

Нужно определить:

- что является узлом;
- что является ребром;
- есть ли веса ребер;
- какие признаки есть у узлов;
- какая задача решается: node classification, link prediction, recommendation, graph classification;
- нужен ли DeepWalk/Node2Vec или GNN/GCN.

Для Node2Vec-рекомендаций:

- построить граф похожести объектов;
- подобрать правило создания ребер;
- обучить эмбеддинги;
- искать ближайшие узлы по cosine similarity;
- оценить рекомендации.

Для GCN:

- использовать признаки узлов и adjacency matrix;
- учитывать self-loops;
- нормализовать агрегацию по степеням;
- сравнить с MLP, чтобы показать пользу структуры графа.

### 7.4. Если задача про мультимодальность

Нужно определить:

- какие есть модальности;
- можно ли объединять их как каналы;
- нужны ли отдельные энкодеры;
- какой fusion использовать;
- требуется ли выравнивание латентных пространств;
- есть ли парные данные для contrastive learning;
- можно ли использовать предобученные модели.

Базовые варианты:

- RGB + Depth как 4-канальный вход в CNN;
- изображение через CNN/ViT + текст через LSTM/Transformer;
- конкатенация эмбеддингов + MLP;
- CLIP embeddings + kNN для поиска;
- frozen encoder + trainable projector.

### 7.5. Если задача про унимодальность

Нужно:

- выбрать представление одной модальности;
- построить baseline;
- корректно разделить данные;
- подобрать гиперпараметры;
- оценить качество на test set.

Унимодальный baseline часто нужен даже в мультимодальной задаче: он показывает, дает ли добавление второй модальности реальный прирост.

## 9. Главная логика курса

Материалы курса показывают, что реальные данные редко бывают простыми:

- классы могут быть несбалансированы;
- объекты могут быть связаны графовой структурой;
- данные могут состоять из нескольких модальностей;
- качество модели нельзя оценивать одной accuracy;
- хорошее решение начинается с правильного представления данных.

Поэтому для лабораторных работ важно не только запустить модель, но и обосновать:

- почему данные представлены именно так;
- почему выбрана эта метрика;
- почему выбран этот способ балансировки или fusion;
- с каким baseline сравнивается результат;
- какие ошибки остаются после улучшений.
